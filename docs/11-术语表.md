## A. 模型与架构

**GGUF**
llama.cpp 使用的模型文件格式。一个文件里包含：元数据（架构、超参）、词表、全部张量权重。
本项目所有模型都是 `.gguf`。

**张量（tensor）**
多维数组，模型权重的统一表示。例如 `ffn_down_exps.weight` 是一个三维张量。

**参数量（parameters）**
模型里所有数值的个数。本项目 74B = 740 亿。
**参数量不等于文件大小**：量化后每个参数占 2–8 bit。

**总参数 / 激活参数（total / active）**
MoE 模型里，总参数是全部专家的和；激活参数是每个 token 实际用到的部分。
Bolt 74B-A9B = 74B 总量，9B 激活。

**MoE（Mixture of Experts，混合专家）**
每层有多个"专家"前馈网络，路由器为每个 token 选 top-k 个。
本模型 top-9，每层专家数 240–496 不等。

**路由器（router / gate）**
决定每个 token 去哪些专家的小矩阵，对应张量 `ffn_gate_inp.weight`。

**共享专家（shared expert，`shexp`）**
每个 token 都会经过的专家，不参与路由选择。

**稠密参数（dense）**
不随 token 变化、每次必读的权重（注意力、SSM、embedding、输出层等）。

**Mamba2 / SSM**
状态空间模型层。用固定大小的状态代替随上下文增长的 KV 缓存。
Bolt 有 40 个 SSM 层。

**注意力层（attention）**
标准 Transformer 层，需要 KV 缓存。Bolt 只有 8 层。

**KV 头（KV head）**
注意力里 key/value 的头数。Bolt 只有 2 个，而 query 头有 32 个（GQA 16:1）。

**GQA（Grouped Query Attention）**
多个 query 头共享一组 KV 头，用来省 KV 缓存。
**本项目的显存问题直接来自"KV 头 2 < 卡数 3"。**

**head_dim**
每个注意力头的维度。Bolt 是 128。

**FFN / 前馈网络**
Transformer 里"升维—激活—降维"的两层矩阵。
`ffn_up` 升维，`ffn_down` 降维。

**latent / 隐向量**
某些层之间的低维中间表示，对应 `ffn_*_latent` 之类的张量。

**视觉投影器（mmproj / vision projector）**
把图像编码器的输出映射到语言模型 embedding 空间的模块。
本项目的 `mmproj-BF16.gguf` 使用 `nemotron_omni` 架构。

## B. 推理与性能

**prefill（预填充）**
处理输入提示的阶段。可以并行处理所有 prompt token，是**计算密集**的。

**decode（解码）**
逐 token 生成的阶段。每步只处理 1 个 token，是**内存带宽密集**的。

**tok/s（tokens per second）**
每秒生成的 token 数。本项目单流 45.8–46.4。

**首 token 时间（TTFT）**
从发出请求到收到第一个 token 的时间，约等于排队 + prefill。

**上下文（context）**
模型一次能看到的 token 总数。本项目可到 1,048,576。

**KV 缓存（KV cache）**
注意力层保存的历史 key/value，避免重复计算。随上下文线性增长。
公式：`2 × 层数 × KV头 × head_dim × 上下文 × 每元素字节`。

**q8_0 / q4_0（KV 量化类型）**
KV 缓存每个元素的存储精度。q8_0 每元素 1 字节，q4_0 约 0.5 字节。

**compute buffer（计算缓冲）**
前向图执行时的临时显存，随 `-ub` 和上下文增长。1M 下约 1.2 GiB/卡。

**GEMV / GEMM**
矩阵-向量乘 / 矩阵-矩阵乘。
decode 是 GEMV（受带宽限制），prefill 是 GEMM（受算力限制）。

**带宽（bandwidth）**
显存每秒能读多少字节。3060 标称 360 GB/s，实测 decode 有效带宽 197–211 GB/s。

**算术强度（arithmetic intensity）**
每读一个字节做了多少次运算。decode 极低，所以瓶颈是带宽不是算力。

**roofline**
把"带宽上限"和"算力上限"画成两条线，用来判断一个负载受哪个限制。
详见 [01-第一性原理](01-第一性原理.md)。

## C. 量化

**量化（quantization）**
把权重从 16/8 bit 压到更少 bit，减小文件、减少每 token 读取量。

**bpw（bits per weight）**
平均每个权重占多少 bit。原版 IQ2 是 2.38，tpfit 是 2.27。

**Q4_K / Q6_K / Q8_0**
k-quant 系列，按块量化，块内有缩放因子。数字越大精度越高、文件越大。

**IQ2_XXS / IQ3_XXS**
i-quant 系列，使用更复杂的码本，同 bit 下质量更好，但**通常需要 imatrix**。

**imatrix（importance matrix）**
量化时用来判断"哪些权重更重要"的统计文件。
IQ 系列目标类型通常需要它；本项目通过"同类型跳过"绕开了这个要求。

**重量化（requantization）**
对已经量化过的模型再次量化。需要 `--allow-requantize`。

**逐张量类型（per-tensor type）**
不同张量用不同精度。通过 `--tensor-type-file` 指定。

**剪枝（pruning）**
删除神经元/权重。**本项目没有做剪枝**，只做了重量化。

**tpfit**
本项目对"为张量并行 + 1M 上下文调整过的混合精度版本"的称呼。
文件后缀 `-tpfit.gguf`。

## D. 并行与切分

**层切分（layer split / pipeline parallel）**
不同层放不同卡。同一时刻只有一张卡在算，是流水线。
`-sm layer`。

**张量并行（tensor parallel）**
每一层内部按维度切到多张卡，每层结束做 all-reduce。
`-sm tensor`。

**all-reduce**
把各卡的部分结果相加并同步到所有卡。张量并行每层都要做。
本项目每 token 约 80 次。

**NCCL**
NVIDIA 的集合通信库，实现 all-reduce 等。没有它 TP 会慢 4 倍。

**rank / world size**
分布式里的进程编号 / 进程总数。本机单机 3 卡，world size = 3。

**镜像（mirrored）**
某个张量无法切分时，每张卡各存一份完整副本。
本项目 KV 缓存就是镜像的（2 个 KV 头 < 3 张卡）。

**`-ts`（tensor split）**
各卡分到的比例。`1,1,1` 表示三等分。

**`-ngl`（n_gpu_layers）**
放 GPU 的层数。`all` 表示全部。

**`-ub`（micro batch / ubatch）**
一次前向处理的 token 数。影响 compute buffer 大小。

**`-np`（parallel slots）**
并发请求槽位数。每个槽位有自己的 KV 缓存。

**`-cmoe` / `-ncmoe`**
专家缓存 / 指定层专家留在 CPU。用于显存不足。
`-cmoe` 与 `-sm tensor` 互斥。

## E. 文件与工具

**llama.cpp**
C/C++ 推理引擎，本项目在其上打了 4 个补丁。

**llama-server**
HTTP 服务，提供 OpenAI 兼容 API 和内置网页。

**llama-quantize**
量化工具，本项目用它生成 tpfit。

**llama-perplexity**
计算 PPL 的工具。

**llama-bench**
基准测试工具。

**mtmd**
llama.cpp 的多模态工具库，负责加载 `mmproj`。

**cmake / ninja**
构建系统。`cmake` 生成配置，`ninja` 执行编译。

**CUDA toolkit**
编译 GPU 代码需要；运行时只需要驱动。

**sm_86**
RTX 3060 的计算能力架构代号。编译时用 `-DCMAKE_CUDA_ARCHITECTURES=86`。

**PPL（perplexity，困惑度）**
语言模型预测下一个 token 的不确定度，越低越好。
只能横向比较同词表模型，不能直接说明任务能力。

**SHA256**
文件内容哈希。用来确认下载/量化产物没有被破坏。

**systemd user unit**
用户级后台服务。本项目用 `bolt-serve.service` 和 `bolt-strata-ui.service`。

**Strata / Trata**
Strata 是一个本地模型管理/聊天前端（MIT）。
Trata 是本项目基于它改名的版本，只改了品牌和主题。

## F. 本项目自造的词

**`LLAMA_SM_TENSOR_ALLOW_ARCH`**
补丁加的环境变量。默认禁止 `nemotron_h_moe` 使用 `-sm tensor`，
设为 `1` 才放行。

**`GGML_TP_NO_REDUCE` / `GGML_TP_AR_STATS`**
诊断开关：跳过 all-reduce / 统计 all-reduce 次数与耗时。生产不要开。

**`GGML_META_*`**
补丁里的图捕获/切分诊断开关，详见 [04-补丁说明](04-补丁说明.md)。

**"三堵墙"**
本项目对 TP 性能上限的总结：带宽墙、通信墙、固定开销墙。

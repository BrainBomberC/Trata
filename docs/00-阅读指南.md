# 00 · 阅读指南

## 这套文档写给谁

- 你有一台多显卡的 Linux 机器，想在本机跑一个"大得看起来不可能"的模型；
- 你听说过量化、张量并行、KV 缓存，但不知道它们之间怎么互相制约；
- 你不想只抄一条命令，而是想**在动手前就知道哪条路必然失败**。

不需要的前置知识：微积分、CUDA 编程、Transformer 论文精读。
需要的基础：会用 Linux 命令行、知道 `git clone` 和 `cmake` 是什么、能看懂"字节 ÷ 带宽 = 时间"。

---

## 三种读法

### A. 我只想尽快跑起来（约 1–2 小时，不含下载）

```
README 第 3 节「复刻路线」
  → docs/03-编译引擎.md
  → docs/05-下载与校验.md
  → docs/06-裁剪与量化.md
  → docs/12-草稿模型与投机解码.md
  → docs/07-启动与调参.md
  → docs/10-排错.md（遇到问题再查）
```

最少需要下载三个文件：主模型、草稿模型（LiLiCorr）、视觉投影器。
`scripts/download-model.sh` 的三个 PRESET 分别对应它们。

### B. 我想先判断"我的机器行不行"（约 30 分钟）

```
docs/01-第一性原理.md  （只需第 1–4 节）
  → docs/02-选型计算.md （照着公式算一遍）
```

算完你会得到三个数：**模型文件上限、每卡显存需求、预期 tok/s**。
如果算出来不成立，就不用下载几十 GB 了。

### C. 我想彻底理解这套系统（约 3–4 小时）

按顺序读 01 → 02 → 03 → 04 → 05 → 06 → 12 → 07 → 08 → 09 → 10 → 11，
最后读 `blog/BLOG.md`。
BLOG 是长文实录，包含更多"当时为什么这么试"的上下文和负结果。

`12-草稿模型与投机解码` 是本版新增的一章：它解释了为什么加上一个 1.11 B 的
小模型能让 74 B 的模型快 15%，以及为什么这个技巧**必须配层切分**、配张量并行反而更慢。

## 约定

- 所有命令默认在**仓库根目录**执行（除非特别说明）。
- `<尖括号>` 是占位符，要替换成你自己的值，例如 `<机器IP>`、`<你的仓库地址>`。
- 命令里的 `python3 -I`：`-I` 表示隔离模式，不加载当前目录的模块，避免被同名文件污染。
- "本机"指作者实测的机器：3×RTX 3060 12 GB、46.9 GiB 内存、Xeon、Ubuntu 24.04。
  **你的数字会不同**，但推导方法相同。

---

## 安全提醒

- 不要为了跑模型去升级 NVIDIA 驱动 / 内核 / firmware。本项目全程只用用户态二进制和 venv。
- `start-ui.sh` 默认把网页监听在 `0.0.0.0:8001`，同一局域网的人都能访问。
  只在本机用就加 `HOST=127.0.0.1`；暴露到公网请自己加反向代理和鉴权。
- 模型许可证独立于本仓库的 MIT 许可证。商用/再分发前读模型页面。

## 一句话版本

> **decode 速度 ≈ 每 token 要读的权重字节 ÷ 有效带宽；模型文件必须比内存小 6–8 GiB；
> 多卡先看层切分（流水线）还是张量并行（真并行），再谈调参。
> 草稿模型一次起草 k 个 token、大模型一次验证，等效于把每 token 的权重读取摊薄到
> `1 + 接受长度` 个 token 上——这是本版从 47 提升到 55 tok/s 的唯一原因。**

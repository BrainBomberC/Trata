# 07 · 启动与调参

这一章给出**可以直接抄**的启动命令，并解释每一个参数存在的理由。
所有命令都在仓库根目录执行。

---

## 1. 启动前检查

```bash
# 1) 三张卡都在、显存干净
nvidia-smi --query-gpu=index,name,memory.used,memory.total --format=csv

# 2) 模型文件在
ls -lh model/bolt74b/*-tpfit.gguf

# 3) NCCL 能被找到
export NCCL_DIR=${NCCL_DIR:-$HOME/nccl-venv/lib/python3.12/site-packages/nvidia/nccl}
ls "$NCCL_DIR/lib/libnccl.so.2"

# 4) 二进制在
ls llama.cpp/build-nccl/bin/llama-server
```

如果 `memory.used` 不是接近 0，先结束上次残留的 `llama-server`：

```bash
pkill -f llama-server
nvidia-smi          # 等显存释放，通常 2–5 秒
```

## 2. 生产配置（3 卡张量并行 + 1M 上下文）

```bash
export LD_LIBRARY_PATH="$NCCL_DIR/lib:$PWD/llama.cpp/build-nccl/bin:$LD_LIBRARY_PATH"
export LLAMA_SM_TENSOR_ALLOW_ARCH=1

./llama.cpp/build-nccl/bin/llama-server \
  -m model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS-tpfit.gguf \
  -ngl all -sm tensor -ts 1,1,1 -fa on \
  -ctk q4_0 -ctv q4_0 -c 1048576 -ub 128 \
  -t 17 -np 1 -fit off \
  -mm model/mmproj-BF16.gguf --no-mmproj-offload \
  --override-kv nemotron_h_moe.context_length=int:1048576 \
  --metrics --host 127.0.0.1 --port 8080 -lv 3
```

启动成功的日志特征：

```
llama_model_load: model size  = 20044.22 MiB
llama_kv_cache: ... size = 2304.00 MiB (per device)
...
main: server is listening on http://127.0.0.1:8080
```

显存应接近：

```
GPU0 11.1 GB / GPU1 11.3 GB / GPU2 11.8 GB
```

### 2.1 用脚本启动

`scripts/run-tp.sh` 把上面的路径、环境变量都参数化了：

```bash
# 前台运行（Ctrl-C 结束）
LLAMA_BIN=$PWD/llama.cpp/build-nccl/bin/llama-server \
NCCL_DIR=$NCCL_DIR \
bash scripts/run-tp.sh

# 后台 + 日志
LOG=/tmp/bolt.log bash scripts/run-tp.sh --daemon

# 看状态 / 停止
bash scripts/run-tp.sh --status
bash scripts/run-tp.sh --stop
```

## 3. 每个参数为什么在这里

| 参数 | 作用 | 不写会怎样 |
|---|---|---|
| `-m <file>` | 模型路径 | 必填 |
| `-ngl all` | 所有层放 GPU | 部分层留在 CPU，慢 3–10 倍 |
| `-sm tensor` | 张量并行（每层切分到 3 卡） | 默认层切分，decode 掉到 40 |
| `-ts 1,1,1` | 三卡等分 | 默认按显存比例，3060 相同则等价；显式写便于排查 |
| `-fa on` | FlashAttention | 长上下文显存暴涨，1M 直接 OOM |
| `-ctk q4_0 -ctv q4_0` | KV cache 量化到 4 bit | 1M 下 KV 4.3 GiB/卡，装不下 |
| `-c 1048576` | 上下文 1M | 默认 4096，长文被截断 |
| `--override-kv ...context_length=int:1048576` | 绕过模型元数据里的 262144 上限 | llama.cpp 会把 `-c` 钳到 262144 |
| `-ub 128` | 物理批大小 | 默认 512，1M 下 KQ mask 让缓冲超显存 |
| `-t 17` | CPU 线程（留 1–2 核给系统） | 默认全核，可能和 CUDA 线程抢核 |
| `-np 1` | 单并发槽 | 默认 1；改大会加倍 KV 缓存 |
| `-fit off` | 关闭显存自动拟合 | 启动时会加载两遍模型"试装"，白等 5–10 分钟 |
| `-mm <mmproj>` | 视觉投影器 | 不能处理图片 |
| `--no-mmproj-offload` | 视觉编码器放 CPU | 编码器占约 1.6 GB 显存，三卡都紧 |
| `--metrics` | 暴露 `/metrics` | 无法用 Prometheus/脚本读 tok/s |
| `--host 127.0.0.1` | 只监听本机 | 默认 0.0.0.0，局域网可访问（有风险，见 08） |
| `-lv 3` | 详细日志 | 出问题时看不到切分/加载细节 |

### 3.1 `-fit off` 到底省了什么

llama.cpp 新版本默认会先加载一遍模型估算每层显存，再调整 `-ngl`/`-ts`。
22 GB 模型在 USB2 盘上加载一遍要 8 分钟，两遍就是 16 分钟。
这里所有参数都手工算好，不需要它拟合。

> 如果你改了卡数或模型，不确定能不能装下，可以先**去掉** `-fit off` 让它自动试一次，
> 记下它算出的结果，再手工固定参数。

### 3.2 为什么 KV 是 q4_0

1M 上下文下 KV 公式：

```
2 × 8 层 × 2 头 × 128 × 1,048,576 × 0.5 B(q4_0) ≈ 2.25 GiB
```

换成 q8_0 就是 4.3 GiB/卡，三卡全部超 12 GB。
200K 上下文则相反：q8_0 只要 850 MiB，精度更高，优先 q8_0。

## 4. 其它可用配置

### 4.1 原版 IQ2 + 张量并行 + 262K（不需要 tpfit）

```bash
./llama.cpp/build-nccl/bin/llama-server \
  -m model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS.gguf \
  -ngl all -sm tensor -ts 1,1,1 -fa on \
  -ctk q8_0 -ctv q8_0 -c 262144 -ub 256 \
  -t 17 -np 1 -fit off \
  --host 127.0.0.1 --port 8080
```

实测 46.8 tok/s，比 1M 配置还略快（KV 更小、mask 更小）。
**如果不需要百万上下文，这是最省事的推荐配置。**

### 4.2 层切分（最稳，prefill 最快）

```bash
./llama.cpp/build-nccl/bin/llama-server \
  -m model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS.gguf \
  -ngl all -sm layer -ts 1,1,1 -fa on \
  -ctk q8_0 -ctv q8_0 -c 204800 -ub 512 \
  -t 17 -np 1 -fit off \
  --host 127.0.0.1 --port 8080
```

- 不需要 NCCL，不需要 `LLAMA_SM_TENSOR_ALLOW_ARCH`；
- decode 40.3 tok/s，prefill 1489 tok/s；
- 三卡是流水线，同一时刻只有一张卡忙——**吞吐不等于三倍**。

### 4.3 显存不够：把专家放内存

```bash
# 稠密权重进显存，专家按需从 RAM 换入
... -cmoe --moe-cache-mib 8192 ...

# 或把 N 层专家留在 CPU
... -ncmoe 8 ...
```

实测 35.7 / 35.0 tok/s。**`-cmoe` 与 `-sm tensor` 互斥**，只能配 `-sm layer`。

### 4.4 多并发

```bash
... -np 4 -c 262144 ...
```

- KV 缓存按槽位复制，`-np 4` 就是 4 份；
- SSM 状态回写在 TP 路径断言 `K == 1`（每个 ubatch 只能有 1 个序列）。
  实测 TP + `-np 4` 聚合 **82.9 tok/s**，但高并发下多个序列被合进同一 ubatch
  会触发断言；生产常驻建议 TP 单槽；
- 需要稳定并发时用 `-sm layer`（4 槽实测只有 33.2 聚合，不如 TP 单流），
  或让请求在客户端排队。

复现 4 路聚合：

```bash
NP=4 CTX=16384 bash scripts/run-tp.sh
```

## 5. 上下文长度的取舍

| 上下文 | KV 类型 | KV/卡 | `-ub` 上限 | decode | 适用 |
|---:|---|---:|---:|---:|---|
| 8K | q8_0 | ~34 MiB | 512 | 46+ | 普通对话 |
| 32K | q8_0 | ~136 MiB | 512 | 46+ | 长文档 |
| 200K | q8_0 | ~850 MiB | 512 | 46.4 | 长文 + 高质量 KV |
| 262K（原生） | q8_0 | ~1.1 GiB | 256 | 46.8 | 原版 IQ2 上限 |
| 1M | q4_0 | ~2.25 GiB | 128 | 45.8–46.4 | 本项目生产 |

> 原生上限 262144 写在 GGUF 元数据里。超过它必须 `--override-kv`，
> 这是"模型没在这么长上训练过"的提示，不是硬错误——但**质量未验证**。

## 6. 启动慢/失败怎么定位

| 阶段 | 正常耗时 | 卡住时看什么 |
|---|---|---|
| 读 GGUF 头 | < 1 s | 文件是否在 USB2 盘/是否损坏 |
| 加载权重 | 3–8 min（USB2） | `-lv 3` 里的 `loading tensor` 进度 |
| 分配 KV | 5–20 s | 是否 OOM，`nvidia-smi` 显存 |
| NCCL 初始化 | 2–10 s | 是否有 `libnccl.so.2` |
| 监听端口 | 立即 | 端口被占用？`ss -ltnp \| grep 8080` |

### 6.1 常见启动错误

| 报错 | 原因 | 处理 |
|---|---|---|
| `arch not supported for tensor split` | 没设 `LLAMA_SM_TENSOR_ALLOW_ARCH=1` | 导出环境变量 |
| `error while loading shared libraries: libnccl.so.2` | `LD_LIBRARY_PATH` 没含 NCCL | 见第 1 节 |
| `CUDA error: out of memory`（device 2） | `-ub` 太大 / 没用 tpfit | `-ub 64` 或换 tpfit |
| `failed to allocate ... KQ mask` | 1M + `-ub 256` | 降到 128 |
| `unknown model architecture 'nemotron_omni'` | 没打 0004 补丁 | 去掉 `-mm` 或用打了补丁的二进制 |
| `tensor 'blk.1.ffn_gate_inp.weight' has wrong shape` | 没打 0001 补丁 | 回到 04 |
| `-cmoe` 抛异常 | 与 `-sm tensor` 同用 | 改 `-sm layer` |
| 启动成功但首 token 极慢 | 首次 CUDA kernel 编译/页缓存冷 | 预热一次即可 |

## 7. systemd 常驻

模板在 `systemd/` 下。安装（用户级，不需要 root）：

```bash
mkdir -p ~/.config/systemd/user
cp systemd/bolt-serve.service ~/.config/systemd/user/
# 编辑里面的 WorkingDirectory / ExecStart / Environment
systemctl --user daemon-reload
systemctl --user enable --now bolt-serve.service
systemctl --user status bolt-serve.service
journalctl --user -u bolt-serve.service -f
```

关键点：

- `Environment=LLAMA_SM_TENSOR_ALLOW_ARCH=1`
- `Environment=LD_LIBRARY_PATH=...`
- `MemorySwapMax=0`：宁可 OOM，也不要静默换页掉到 0.04 tok/s；
- `Restart=on-failure`，但 OOM 会反复重启——先修配置。

## 8. 停止与清理

```bash
# 前台：Ctrl-C
# 后台脚本：
bash scripts/run-tp.sh --stop

# 手工：
pkill -f 'llama-server.*bolt74b'
sleep 3
nvidia-smi
```

如果显存没释放，说明进程还在退出中（保存 KV/释放 CUDA context），再等几秒。
仍然不释放就 `nvidia-smi --gpu-reset`（需要 root，且会杀掉该卡上所有进程）。

# 10 · 排错

按"你在哪一步"查找。每条都给出**症状 → 原因 → 验证 → 处理**。

先记住三条通用命令：

```bash
nvidia-smi                                   # 显存/进程/利用率
journalctl --user -u bolt-serve -n 100       # systemd 日志
pkill -f llama-server && sleep 3             # 清理残留
```

---

## 1. 下载阶段

### 1.1 文件大小对，SHA 不对

**原因**：续传拼接错位、代理返回了错误页、磁盘写坏。

**验证**：

```bash
stat -c%s model/bolt74b/*.gguf
sha256sum model/bolt74b/*.gguf
```

先看大小：如果只差 **64 字节**，这是已知的元数据变体（`docs/05 §4.2`），
不是损坏。确认张量清单一致即可继续。

**处理**（真的损坏时）：删掉最终文件和分块，重下。不要试图修补。

```bash
rm -f model/bolt74b/*.gguf model/bolt74b/.chunks-*
bash scripts/download-model.sh
```

草稿和投影器同理：

```bash
PRESET=draft  bash scripts/download-model.sh
PRESET=mmproj bash scripts/download-model.sh
```

### 1.2 下载速度只有几十 KB/s

**原因**：走了代理、DNS 解析到境外、或用了 HF 直连。

**验证**：

```bash
env | grep -i proxy
curl -sI --noproxy '*' https://modelscope.cn | head -3
```

**处理**：确保 ModelScope 走直连（脚本已默认 `--noproxy '*'`）；
HF 源在国内基本不可用，优先 ModelScope。

### 1.3 磁盘写满

22 GB 文件下载需要约 44 GB（分块 + 最终文件）。

```bash
df -h .
du -sh model/bolt74b/.chunks-* 2>/dev/null
```

清理旧模型/缓存后再下。

## 2. 编译阶段

### 2.1 `unsupported GNU version`

**原因**：CUDA 12.0 不认识 GCC 13。

**处理**：

```bash
sudo apt install g++-12
cmake ... -DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-12
```

### 2.2 `Could NOT find NCCL`

**原因**：CMake 找不到 wheel 里的 NCCL。

**处理**：

```bash
export NCCL_DIR=~/nccl-venv/lib/python3.12/site-packages/nvidia/nccl
ls "$NCCL_DIR/include/nccl.h" "$NCCL_DIR/lib/libnccl.so.2"
cmake ... -DNCCL_INCLUDE_DIR="$NCCL_DIR/include" \
          -DNCCL_LIBRARY="$NCCL_DIR/lib/libnccl.so.2"
```

### 2.3 `fatal error: curl/curl.h`

**原因**：开了 `LLAMA_CURL` 但没装 `libcurl-dev`。

**处理**：`-DLLAMA_CURL=OFF`，用脚本下载模型。

### 2.4 编译 OOM 或极慢

```bash
free -g
nproc
```

`-j` 降到核数的一半；16 GB 内存的机器用 `-j 4`。

### 2.5 编译成功但 `ldd` 没有 nccl

**原因**：`GGML_CUDA_NCCL` 没生效，或链接到了错误的库。

```bash
grep -i nccl build-nccl/CMakeCache.txt
ldd build-nccl/bin/llama-server | grep nccl
```

必须看到 `libnccl.so.2 => ...`。没有就重跑 cmake，确认 cache 被清掉：

```bash
rm -rf build-nccl
```

## 3. 补丁阶段

### 3.1 `git apply --check` 失败

**原因**：上游版本不对，或者补丁组和基线不匹配。

| 补丁 | 必须的基线 |
|---|---|
| `0005-lilicorr-dflash.patch` | `5aeac37a35b44fde4bdffaec9159f2fcb253b622` |
| `0001`–`0004` | `69f201a2051ea9b9e9b50c3cc56afd9e2ae64414` |

**验证**：

```bash
git log -1 --format='%H %s'
```

**处理**：

```bash
# 生产
git checkout 5aeac37a35b44fde4bdffaec9159f2fcb253b622
git status --short          # 必须是干净的
git apply ../patches/0005-lilicorr-dflash.patch

# 回退
git checkout 69f201a2051ea9b9e9b50c3cc56afd9e2ae64414
for p in ../patches/000[1-4]-*.patch; do git apply "$p"; done
```

如果之前打过补丁，先 `git checkout -- .` 再重来。
**不要**把 0001–0004 和 0005 打在同一个 checkout 上。

### 3.2 补丁打上了但编译报错

**原因**：混用了不同版本的源码，或有残留的 `.orig` / `.rej`。

```bash
find llama.cpp -name '*.rej' -o -name '*.orig'
git -C llama.cpp status --short
```

清理后从干净 checkout 重打。

## 4. 量化阶段

### 4.1 配方没生效（输出大小不对）

**原因**：`--tensor-type-file` 放到了位置参数后面。

**验证**：

```bash
grep -c '=' /tmp/tpfit-types.txt     # 240
head -3 /tmp/tpfit-types.txt
```

**处理**：把选项全部放在输入/输出文件名之前。

### 4.2 `imatrix required`

**原因**：目标 IQ 类型与现有类型不同，且没有 imatrix。

**处理**：确认输入是官方 `IQ2_XXS`（专家已经是 `iq2_xxs`），
并确认打了 0003 补丁（同类型跳过）。

### 4.3 量化中途被杀

**原因**：内存不足 / 磁盘满 / SSH 断开。

**处理**：用 `nohup` 或 `tmux` 跑；检查 `dmesg | tail` 是否有 OOM killer。

```bash
nohup bash scripts/quantize-tpfit.sh > /tmp/quant.log 2>&1 &
tail -f /tmp/quant.log
```

## 5. 加载阶段

### 5.1 `tensor 'blk.1.ffn_gate_inp.weight' has wrong shape`

**原因**：没打 0001 补丁（逐层专家数）。

**处理**：见 [04-补丁说明](04-补丁说明.md)。

### 5.2 `arch not supported for tensor split`

**原因**：没设 `LLAMA_SM_TENSOR_ALLOW_ARCH=1`，或没打 0002 补丁。

```bash
export LLAMA_SM_TENSOR_ALLOW_ARCH=1
```

### 5.3 `unknown model architecture 'nemotron_omni'` / `'dflash'`

**原因**：引擎版本不对。

- `nemotron_omni`（视觉）：回退组没打 0004，或用了更旧的树；
- `dflash`（草稿）：引擎不支持 LiLiCorr，必须用 `5aeac37` + 0005。

**处理**：换引擎；只做文字推理时可以先去掉 `-mm` / `-md` 验证。生产配置**不能**去掉 `-md`，
否则回到 40 tok/s（层切分无草稿）。

### 5.4 `error while loading shared libraries: libnccl.so.2`

```bash
export LD_LIBRARY_PATH="$NCCL_DIR/lib:$PWD/llama.cpp/build-nccl/bin:$LD_LIBRARY_PATH"
ldd llama.cpp/build-nccl/bin/llama-server | grep nccl
```

### 5.5 加载卡在某个张量

**原因**：模型在 USB2 盘上（43.8 MB/s），22 GB 需要约 8 分钟。

**验证**：

```bash
iostat -x 1        # 看 sda/nvme 的读速率
```

**处理**：把模型拷到 NVMe；或在启动前 `vmtouch` 预热页缓存。

### 5.6 GGUF 损坏 / `failed to read tensor`

**处理**：

```bash
sha256sum model/bolt74b/*.gguf
```

SHA 不对就重下。SHA 对但仍失败，检查磁盘 `dmesg | grep -i error`。

### 5.7 草稿模型相关

| 症状 | 原因 | 处理 |
|---|---|---|
| `unknown model architecture 'dflash'` | 引擎不支持 LiLiCorr | 用 `5aeac37` + 0005 重编 |
| 启动 OOM，日志卡在 draft | TP + 1M + 草稿装不下 | 改 `-sm layer`（生产默认） |
| 加载了草稿但速度没变 | 没给 `--spec-type draft-dflash`，或 `-md` 路径错 | 用 `scripts/run-draft.sh` |
| 速度只有 20 出头 | 草稿跑在 CPU（`-ngld 0` / 显卡不够） | `NGLD=all`；检查 `nvidia-smi` |
| 接受长度很低（< 1.5） | 温度太高、任务太发散，或 `n_max` 太大 | 降 `NMAX`；温度 0–0.7 之间比较 |
| 1M 预填充极慢 | 草稿也要过一遍 prompt | 正常代价；改用 TP 回退或缩短 prompt |
| `-ub 128/256` 时 OOM | 验证批次放大 | `UB=64` |

排查时先确认三件事：

```bash
# 1) 草稿文件在
ls -lh model/draft/*.gguf
# 2) 启动参数里有 -md / --spec-type
bash scripts/run-draft.sh --status
# 3) 日志里有 draft / acceptance
grep -iE 'draft|accept' model/bolt-serve.log | tail -20
```

## 6. 显存 / OOM

### 6.1 `CUDA error: out of memory`（启动时）

按顺序尝试：

1. `-ub 64`（1M 下最有效，省约 0.3 GiB）；
2. 确认是 `-sm layer`（生产默认）。**TP + 1M + 草稿必然 OOM**；
3. 降上下文（1M → 262K，KV 总量从 2.25 GiB 降到 1.1 GiB，按层分布后每卡更小）；
4. KV 换 q4_0（如果还不是）；
5. 去掉 `-mm` / 确认 `--no-mmproj-offload`；
6. 只有回退组才考虑换 `tpfit`（少约 0.31 GiB/卡）。

### 6.2 OOM 发生在生成过程中

**原因**：KV 随上下文增长，短提示能跑不代表长提示能跑。

```bash
nvidia-smi --query-gpu=memory.used --format=csv -l 1
```

看哪张卡先满。1M 下三卡分别 11.1/11.3/11.8 GB，余量本来就小。

### 6.3 显存没释放

```bash
pkill -f llama-server
sleep 5
nvidia-smi
```

仍有占用：

```bash
nvidia-smi --query-compute-apps=pid,used_memory --format=csv
```

按 PID 确认是不是自己的进程。**不要**随手 `nvidia-smi --gpu-reset`，
它会杀掉该卡上所有进程。

### 6.4 速度突然掉到个位数

**原因**：模型被换出到磁盘（内存不足）。

**验证**：

```bash
free -g
iostat -x 1        # 持续 20–30 MB/s 读盘 = 在掉盘
```

**处理**：换更小的量化；或加内存。`swap` 帮不了——见 02。

## 7. 张量并行 / NCCL

### 7.1 启动即卡住（无日志）

**原因**：NCCL 初始化等待所有 rank/设备。

**验证**：

```bash
NCCL_DEBUG=INFO LLAMA_SM_TENSOR_ALLOW_ARCH=1 \
  ./llama.cpp/build-nccl/bin/llama-server ... 2>&1 | grep -i nccl | head -40
```

常见：

| 日志 | 原因 |
|---|---|
| `NCCL WARN Bootstrap : no socket interface found` | 网卡/防火墙 |
| `NCCL WARN Connect to ... failed` | 多机配置错误（本机单机不需要） |
| `invalid device ordinal` | `-ts` 条目数与 GPU 数不符 |

### 7.2 输出乱码

**原因**：可能开了 `GGML_TP_NO_REDUCE` 之类的诊断开关（会跳过 all-reduce）。

```bash
env | grep GGML_
```

清掉这些环境变量再启动。

### 7.3 TP 比层切分还慢

**原因**：没链上 NCCL，退化成主机内存归约（慢 4 倍）。

```bash
ldd llama.cpp/build-nccl/bin/llama-server | grep nccl
grep -o 'GGML_USE_NCCL' build-nccl/ggml/src/ggml-cuda/CMakeFiles/ggml-cuda.dir/flags.make
```

### 7.4 单卡利用率 100%，另外两张很低

**原因**：用了 `-sm layer`（流水线，同一时刻只有一张卡忙）。

这是正常现象。要三卡同时忙用 `-sm tensor`。

### 7.5 三卡利用率都高但 tok/s 只有 20 多

**原因**：可能在跑 4 路并发（每路 24 tok/s，聚合 82.9），或者 PCIe 链路降速。

```bash
nvidia-smi --query-gpu=pcie.link.gen.current,pcie.link.width.current --format=csv
```

x4/x1 会显著拖慢 all-reduce。

## 8. 网页 / API

### 8.1 页面空白

```bash
ls ui/strata/index.html
python3 -I scripts/serve-ui.py    # 必须从仓库根目录启动
```

`serve-ui.py` 用 `__file__` 的上一级找 `ui/`，从别的目录启动也能找到；
但如果整个目录结构被移动，就会 404。

### 8.2 `/health` 返回 `loading`

说明 8080 后端没起来：

```bash
curl -s http://127.0.0.1:8080/health
ss -ltnp | grep 8080
```

### 8.3 tok/s 显示 `–`

后端启动时没加 `--metrics`。

### 8.4 流式输出卡住

**原因**：反向代理缓冲（nginx）或客户端没处理 SSE。

```bash
curl -N http://127.0.0.1:8001/v1/chat/completions ...   # -N 禁用缓冲
```

nginx 需要 `proxy_buffering off;`。

### 8.5 `/v1/messages` 404

**原因**：当前 llama.cpp 构建没开 Anthropic 兼容层。

**验证**：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/v1/messages \
  -H 'Content-Type: application/json' -d '{}'
```

404 就换回项目钉的 commit，或改用 `/v1/chat/completions`。

## 9. systemd

### 9.1 服务起不来

```bash
systemctl --user status bolt-serve.service
journalctl --user -u bolt-serve.service -n 80 --no-pager
```

常见：

| 报错 | 原因 |
|---|---|
| `ExecStart=... No such file` | 路径写错；systemd 不展开 `~`，用绝对路径 |
| `status=203/EXEC` | 二进制没有执行权限 / 解释器路径错 |
| `status=217/USER` | `User=` 写错（用户级服务不需要） |
| 启动成功但立刻退出 | `LD_LIBRARY_PATH` 没设，找不到 `libnccl.so.2` |

### 9.2 开机不启动

```bash
loginctl show-user "$USER" | grep Linger
sudo loginctl enable-linger "$USER"
```

用户级服务默认要等用户登录；`enable-linger` 后开机即启动。

### 9.3 反复重启

`Restart=on-failure` + OOM 会形成重启风暴。
先 `systemctl --user stop`，修好显存配置再启用。

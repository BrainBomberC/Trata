## 3. 打补丁

```bash
for p in ../patches/*.patch; do
  echo "== $p"
  git apply --check "$p"       # 先干跑，失败会立刻报
  git apply "$p"
done
```

四个补丁的作用：

| 补丁 | 文件数 | 作用 | 不打会怎样 |

## 4. 准备 NCCL

### 4.1 系统里已有

```bash
ldconfig -p | grep nccl
```

### 4.2 没有：从 Python wheel 取（推荐，免 root）

```bash
python3 -m venv ~/nccl-venv
~/nccl-venv/bin/pip install nvidia-nccl-cu12
find ~/nccl-venv -name 'libnccl.so*'
```

得到目录形如：

```
~/nccl-venv/lib/python3.x/site-packages/nvidia/nccl/lib/libnccl.so.2
```

把它记成 `NCCL_DIR`：

```bash
export NCCL_DIR=~/nccl-venv/lib/python3.x/site-packages/nvidia/nccl
ls "$NCCL_DIR/lib/libnccl.so.2"
```

### 4.3 为什么一定要 NCCL

张量并行每层都要 all-reduce。没有 NCCL 时，llama.cpp 会退化成主机内存搬运：

| 配置 | 200K prefill |
|---|---:|
| 有 NCCL | 781 tok/s |
| 无 NCCL | 185 tok/s（慢 4 倍） |

## 5. 配置与编译

```bash
cd ~/Nemotron3Super/llama.cpp

cmake -B build-nccl \
  -DGGML_CUDA=ON \
  -DGGML_CUDA_NCCL=ON \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_ARCHITECTURES=86 \
  -DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-12 \
  -DNCCL_INCLUDE_DIR="$NCCL_DIR/include" \
  -DNCCL_LIBRARY="$NCCL_DIR/lib/libnccl.so.2"

cmake --build build-nccl -j 8 \
  --target llama-server llama-quantize llama-perplexity
```

参数解释：

| 参数 | 为什么 |
|---|---|
| `GGML_CUDA=ON` | 启用 CUDA 后端 |
| `GGML_CUDA_NCCL=ON` | 启用 NCCL all-reduce（张量并行必需） |
| `CMAKE_CUDA_ARCHITECTURES=86` | RTX 3060 是 sm_86；不写会编译很多架构，慢且大 |
| `CMAKE_CUDA_HOST_COMPILER` | CUDA 12.0 的 `host_config.h` 拒绝 GCC 13；用 g++-12 |
| `NCCL_INCLUDE_DIR` / `NCCL_LIBRARY` | CMake 找不到 wheel 里的 NCCL，显式指定 |

**如果系统 g++ 就是 12**，可以去掉 `CMAKE_CUDA_HOST_COMPILER`。
**如果 CUDA 是 12.4+**，通常已支持 GCC 13，也可以去掉。

### 5.1 没有 libcurl 怎么办

本项目的树默认关闭 `LLAMA_CURL`，因此：

- 不能用 `-hf <repo>` 让 llama.cpp 自动下载模型；
- 必须用本仓库的 `scripts/download-model.sh` 先下好。

这是刻意的：服务器上往往没有 `libcurl-dev`，而下载脚本需要断点续传和 SHA 校验，
用 bash/curl 更可控。

### 5.2 编译时间与产物

| 项 | 参考 |
|---|---|
| 8 核编译 | 15–30 分钟 |
| 产物目录 | `build-nccl/bin/` |
| 关键二进制 | `llama-server`、`llama-quantize`、`llama-perplexity` |
| 体积 | 约 2–4 GB |

## 6. 验证 NCCL 真的链上了

**这一步不能跳过。** 编译成功不等于链接了 NCCL。

```bash
# 1) 编译标志
grep -o 'GGML_USE_NCCL' \
  build-nccl/ggml/src/ggml-cuda/CMakeFiles/ggml-cuda.dir/flags.make

# 2) 动态链接
ldd build-nccl/bin/llama-server | grep nccl
# 预期：libnccl.so.2 => /.../libnccl.so.2

# 3) 运行时能找到
LD_LIBRARY_PATH="$NCCL_DIR/lib:$PWD/build-nccl/bin" \
  build-nccl/bin/llama-server --version
```

如果第 2 步没有输出，说明 `GGML_CUDA_NCCL` 没生效。检查：

```bash
grep -i nccl build-nccl/CMakeCache.txt
```

## 7. 常见编译错误

| 报错 | 原因 | 处理 |
|---|---|---|
| `error: #error -- unsupported GNU version` | CUDA 12.0 + GCC 13 | 加 `-DCMAKE_CUDA_HOST_COMPILER=/usr/bin/g++-12` |
| `Could NOT find NCCL` | CMake 找不到 wheel 里的库 | 显式 `-DNCCL_INCLUDE_DIR=... -DNCCL_LIBRARY=...` |
| `fatal error: curl/curl.h` | 开了 `LLAMA_CURL` | 加 `-DLLAMA_CURL=OFF`，用脚本下载 |
| `undefined reference to ncclCommInitRank` | 链接了头但没链接库 | 检查 `NCCL_LIBRARY` 指向 `libnccl.so.2` 而不是 `.so` |
| 编译到一半 OOM | `-j` 太大 | 降到 `-j 4` |
| `nvcc fatal: Unsupported gpu architecture 'compute_86'` | CUDA 版本过老 | 升级 CUDA toolkit；或去掉 `CMAKE_CUDA_ARCHITECTURES` |

## 8. 运行时库路径

启动 llama-server 前必须：

```bash
export LD_LIBRARY_PATH="$NCCL_DIR/lib:$PWD/build-nccl/bin:$LD_LIBRARY_PATH"
export LLAMA_SM_TENSOR_ALLOW_ARCH=1
```

- `LD_LIBRARY_PATH`：否则 `error while loading shared libraries: libnccl.so.2`；
- `LLAMA_SM_TENSOR_ALLOW_ARCH=1`：补丁加的开关，允许 `nemotron_h_moe` 使用 `-sm tensor`。

`scripts/run-tp.sh` 已经处理了这两项。下一章解释补丁具体改了什么。

# 04 · 补丁说明：为什么需要改 llama.cpp

补丁有 **5 个，分两组**，对应两个上游快照：

| 组 | 补丁 | 上游 | 解决什么 |
|---|---|---|---|
| 回退 | 0001–0004 | `69f201a` | 逐层专家数、Mamba2 张量并行、重量化跳过同类型、`nemotron_omni` 视觉 |
| **生产** | 0005 | `5aeac37` | LiLiCorr(DFlash) 草稿在层切分 / TP 下能跑，且预填充不退化 |

回退组的四个补丁解决的是"上游根本跑不了"：

1. 不能正确处理"每层专家数不同"的 GGUF；
2. 不能对 SSM/Mamba2 层做张量并行；
3. 重量化时不会跳过已经同类型的张量；
4. 不识别 `nemotron_omni` 视觉投影器。

生产组只差一件事：上游 master 已经能加载模型、能做层切分，但 **DFlash 草稿模型**
要求在全词表上做 top-k，并且它的候选构造用到了 meta 后端不认识的算子。

这些**不是**官方代码，属于实验性移植；仓库把两个上游 commit 都钉死，并提供逐字节验证。

## 0. 应用方式

**生产（只打 0005）**：

```bash
cd llama.cpp
git checkout 5aeac37a35b44fde4bdffaec9159f2fcb253b622
git apply --check ../patches/0005-lilicorr-dflash.patch
git apply         ../patches/0005-lilicorr-dflash.patch
```

**回退（打 0001–0004）**：

```bash
cd llama.cpp
git checkout 69f201a2051ea9b9e9b50c3cc56afd9e2ae64414
for p in ../patches/000[1-4]-*.patch; do
  git apply --check "$p" && git apply "$p"
done
```

同一组内补丁之间修改的文件不重叠，**顺序无所谓**，但建议按编号应用以便排查。
**跨组不要混用**：0001–0004 对 `5aeac37` 不保证能打上，0005 对 `69f201a` 也不行。

验证：

```bash
# 生产：4 个 M
git status --short | wc -l          # 4

# 回退：22（21 修改 + 1 新增）
git status --short | wc -l          # 22
git diff --stat | tail -1
```

## 第一部分：回退组（0001–0004，对 `69f201a`）

> 只有你要跑 **TP×3 回退配置**时才需要这四个补丁。生产配置（层切分 + 草稿）不需要。

## 1. `0001-nemotron-per-layer-expert-count.patch`

**改动文件**：`src/models/nemotron-h.cpp`（1 个）

### 问题

Bolt 74B 的 40 个 MoE 层，专家数并不相同：

```
240 × 12 层, 304 × 6 层, 368 × 9 层, 432 × 10 层, 496 × 3 层
```

但 GGUF 元数据只有一个标量 `nemotron_h_moe.expert_count = 496`。
上游按这个标量去校验每一层的路由器张量，于是第一层就报：

```
check_tensor_dims: tensor 'blk.1.ffn_gate_inp.weight' has wrong shape;
expected 4096,496 got 4096,240
```

### 改法

创建张量和构建前向图时，**改用该层路由器张量的实际形状**，而不是全局标量：

```cpp
// 创建时
const auto * router_meta = ml.get_tensor_meta(
    tn(LLM_TENSOR_FFN_GATE_INP, "weight", i).str().c_str());
const int64_t n_expert_layer = router_meta ? router_meta->ne[1] : n_expert;

// 前向图里
build_moe_ffn(..., model.layers[il].ffn_up_exps->ne[2], ...);
```

这是从上游后续版本回补的思路。**不打这个补丁，模型根本加载不了。**

## 2. `0002-tensor-parallel.patch`

**改动文件**（11 个）：

```
ggml/include/ggml.h
ggml/include/ggml-backend.h
ggml/src/ggml.c
ggml/src/ggml-backend.cpp
ggml/src/ggml-backend-impl.h
ggml/src/ggml-backend-meta.cpp
ggml/src/ggml-cuda/ggml-cuda.cu
ggml/src/ggml-cuda/ssm-scan.cu
src/llama-arch.cpp
src/llama-model.cpp
src/models/mamba-base.cpp
```

这是最大、最复杂的补丁（约 1400 行 diff）。

### 2.1 架构门禁（`src/llama-arch.cpp`）

上游：

```cpp
bool llm_arch_supports_sm_tensor(llm_arch arch) {
    case LLM_ARCH_NEMOTRON_H_MOE: return false;   // 默认关闭
    ...
}
```

补丁增加环境变量开关：

```bash
export LLAMA_SM_TENSOR_ALLOW_ARCH=1
```

默认行为不变（仍返回 false）。这是一个**安全阀**：只有明确知道自己在做什么的人才打开。

### 2.2 Mamba2 的切分规格（`src/llama-model.cpp`）

这是整个移植最难的部分。SSM 层不是标准注意力，不能简单按输出维度切。

融合投影 `ssm_in`（4096 → 18560）的内部布局是：

```
[ z(8192) | x(10240) | dt(128) ]
```

补丁把它切成 **5 段**（z / x / B / C / dt），每段有各自的切分粒度。
如果整块按一个维度切，conv1d、scan、分组 norm 会跨卡，切分推断直接失败：

```
GGML_ASSERT(ret.axis != UNKNOWN) failed
```

关键对齐约束：

```
d_inner = 8192 = 8 组 × 1024 通道
n_head  = 128 头；每组 16 头（hpg = 16）
head_dim = 64
切分粒度必须是 1024 的倍数
```

其它规则：

- 按张量计算 block 大小的最小公倍数（lcm），保证每张卡的分块边界一致；
- `n_gqa == 0` 时不做头切分（避免除零 / 错误推断）；
- 任一维度算出来为 0 → 该张量改为**镜像**而不是切分；
- 2 个 KV 头 < 3 张卡 → KV 缓存镜像（这正是 1M 显存吃紧的根源）。

### 2.3 SSM scan 的多后端处理

`ggml/src/ggml-backend-meta.cpp` 新增 `handle_ssm_scan`：

- `s` 在 axis 2；
- `x` 在 axis 1；
- `dt` 在 axis 0；
- `A` 在 axis 1；
- `B` / `C` 在 axis 1。

不同源张量的头在**不同轴**上，必须分别处理，不能套用统一的切分模板。

同时增加几个诊断/实验开关：

| 环境变量 | 用途 |
|---|---|
| `GGML_META_GRAPH_CAPTURE` | 整段图捕获（实验，实测更慢） |
| `GGML_META_NO_NCCL` | 关闭 meta 后端里的 NCCL（对照实验） |
| `GGML_META_TS` | 打印/控制切分 |
| `GGML_META_HOST_DELAY_US` | 人为注入主机延迟，测通信敏感性 |

### 2.4 扫描核（`src/models/mamba-base.cpp`、`ssm-scan.cu`）

`build_mamba2_layer` 改用两个输出：

```cpp
ggml_ssm_scan_y(...)       // 序列输出
ggml_ssm_scan_state(...)   // 最终状态
```

并加断言 `GGML_ASSERT(K == 1)`：当前实现按 ubatch 回写状态，要求**每个 ubatch 只含 1 个序列**。
`ggml/src/ggml.c` 里 mode=2 的输出形状改为按序列而非按槽位。

### 2.5 CUDA 侧（`ggml-cuda.cu`）

新增：

- 后端图捕获接口实现（`g_capture_depth`）；
- `GGML_TP_NO_REDUCE`：跳过 all-reduce（只用于定位通信成本，输出会乱码）；
- `GGML_TP_AR_STATS`：统计 all-reduce 次数与耗时。

这些主要是**诊断工具**，生产默认不开启。

### 2.6 不打会怎样

| 场景 | 结果 |
|---|---|
| 不打补丁，跑 `-sm layer` | 可以（只需要 0001） |
| 不打补丁，跑 `-sm tensor` | 被架构门禁拒绝：`arch not supported` |
| 只打 0001 + 0002 但没设环境变量 | 仍然被门禁拒绝 |
| 设了环境变量但没打 0002 | 切分断言失败 / 形状错误 |

## 3. `0003-quantize-same-type.patch`

**改动文件**：`src/llama-quant.cpp`（1 个）

### 问题

tpfit 配方把专家张量钉成 `iq2_xxs`，而源文件里专家**本来就是 `iq2_xxs`**。
上游 `llama-quantize` 仍会尝试"重新量化"，于是：

- IQ 系列目标类型需要 imatrix，缺失时报错；
- 即使能跑，也会白白重算 160 个大张量，增加几十分钟和精度损失。

### 改法

在 `llama_model_quantize_impl` 里，目标类型与源类型相同时**直接跳过**，保留原始字节。
日志里表现为这些张量只打印大小、不打印 `converting to`。

### 影响

- 只影响"重量化"路径，不影响正常量化；
- 让 tpfit 配方可以在没有 imatrix 的情况下复现；
- 输出文件大小与逐张量类型清单严格对应。

## 4. `0004-vision-nemotron-omni.patch`

**改动文件**（9 个）：

```
tools/mtmd/clip.cpp
tools/mtmd/clip-impl.h
tools/mtmd/clip-model.h
tools/mtmd/CMakeLists.txt
tools/mtmd/models/models.h
tools/mtmd/mtmd.cpp
tools/mtmd/mtmd-image.cpp
tools/mtmd/mtmd-image.h
tools/mtmd/models/nemotron-omni.cpp   ← 新文件
```

### 问题

Bolt 的多模态投影器（`mmproj-BF16.gguf`）使用 `nemotron_omni` 架构。
上游 mtmd 没有这个模型类型，`-mm` 会报：

```
error: unknown model architecture 'nemotron_omni'
```

### 改法

新增 `tools/mtmd/models/nemotron-omni.cpp`，实现：

- 投影器图构建（视觉编码器输出 → 语言模型 embedding 空间）；
- 图像预处理参数（patch 大小、归一化、token 数）；
- 在 `clip-model.h` / `models.h` 注册架构与工厂函数；
- `mtmd-image.cpp` 增加对应的图像切分/尺寸处理；
- `CMakeLists.txt` 加入新源文件。

### 现状与限制

- 视觉路径可用，但**不是**本项目的性能重点；
- 张量布局有两种：Bolt 仓库那份是 **519 个张量、q/k/v 分开**；
  120B/Super 仓库的同名文件是 **393 个张量、fused `attn_qkv`**。
  `build_vit` 两条分支都能**加载**，但只有 Bolt 那份给出正确的图像特征——
  393 那份不报错、图像描述却全错。**认仓库和 SHA，不要认文件名**；
- 生产命令用 `--no-mmproj-offload` 把编码器放 CPU，节省显存；
- 如果只需要文本，不下载 mmproj 即可，补丁也不影响文本推理。

## 第二部分：生产组（0005，对 `5aeac37`）

## 5. `0005-lilicorr-dflash.patch`

**改动文件**（4 个，+50 / −5 行）：

```
src/models/mamba-base.cpp
src/llama-arch.cpp
src/llama-model.cpp
ggml/src/ggml-backend-meta.cpp
```

### 问题

上游 master 已经能加载 Bolt、能做层切分、能识别视觉投影器，但没有为
**LiLiCorr/DFlash 草稿 + 混合 Mamba 目标**准备好这四处细节：

1. **草稿的 head 要在全词表上取 top-k。** DFlash 草稿的 `output.weight`
   必须整份可用，不能被切分；Mamba 层的 SSM 权重和状态也必须整份镜像，
   否则草稿和目标的隐藏状态对不上。
2. **草稿的候选构造用了 `GGML_OP_ARANGE`。** meta 后端（`-sm tensor` 时走它）
   不认识这个算子，直接 abort。
3. **Mamba 层没有 KV 头。** 计算注意力切分粒度时会 `n_head_kv(il) == 0`，
   上游直接拿它做除数，触发除零/断言。
4. **开草稿后 `n_rs_seq` 变成 `n_max+1`。** 这个值被 Mamba 预填充的
   SSD kernel 当成了序列长度维度，导致**整个 prompt 的预填充按 9 倍状态展开**。
   长上下文下预填充会慢到不可用。补丁只在验证批次用大 `K`，预填充保持 `K=1`。

### 改法

| 文件 | 改动 |
|---|---|
| `src/models/mamba-base.cpp` | `K_rs = n_rs_seq`（>0 时）+1；构造 `K = (n_seq_tokens > K_rs) ? 1 : K_rs`——大 ubatch（预填充）用 1，小批次（验证）才用 `K_rs` |
| `src/llama-model.cpp` | 把 `NEMOTRON_H` / `NEMOTRON_H_MOE` 的 SSM 权重、状态、`output.weight` 以及 DFlash 草稿全部标记 MIRRORED；在 `n_head_kv(il) > 0` 时才计算注意力粒度 |
| `src/llama-arch.cpp` | 从 `-sm tensor` 的禁用架构名单里移除 `NEMOTRON_H` / `NEMOTRON_H_MOE` |
| `ggml/src/ggml-backend-meta.cpp` | `GGML_OP_ARANGE` 的输出标记为 MIRRORED |

### 为什么补丁里没有调试输出

开发时曾在 `llama-model.cpp` 里临时加了两个 `fprintf` 块
（`[META-GENERIC-UNKNOWN]`、`[META-PERROW]`），用来定位哪些张量没有切分规则。
发布版通过在一个干净的 worktree 里重新生成 diff 把它们剥掉了，
所以这份补丁可以直接进生产，不会往日志里刷屏。

### 生产组与回退组的关系

- **层切分不需要** meta 后端，所以 `llama-model.cpp`、`ggml-backend-meta.cpp`、
  `llama-arch.cpp` 的改动在 `-sm layer` 下不生效；它们是为"TP + 草稿"准备的。
- **`mamba-base.cpp` 的改动对两种切分都生效**，是长上下文预填充性能的关键。
- 即使你只跑层切分 + 草稿，也要打完整 0005——只挑一个文件会让补丁无法应用。

补丁逐行内容见 [patches/0005-lilicorr-dflash.patch](../patches/0005-lilicorr-dflash.patch)。

## 6. 补丁的边界与风险

1. **两组各自只对一个基线验证过**：0001–0004 对 `69f201a`，0005 对 `5aeac37`。
   上游一改 `llama-model.cpp` 的切分逻辑，补丁就可能冲突。升级前先 `git apply --check`。
2. **不是上游质量**。缺少完整测试、边界用例和跨架构验证。
   如果上游后续正式支持 `nemotron_h_moe` 的 TP 或 LiLiCorr 的层切分，
   应优先使用上游实现。
3. **默认关闭**。`LLAMA_SM_TENSOR_ALLOW_ARCH=1` 是显式 opt-in，不会影响普通模型。
4. **回退组的 ubatch 单序列限制**。回退组的 SSM 状态回写断言 `K == 1`。实测 TP + `-np 4`
   可以达到 82.9 tok/s 聚合，但多个序列被合进同一 ubatch 时会触发断言；
   回退组建议 TP 单槽。生产组（0005）把 `K` 改成按批次大小自适应，没有这个限制。

## 7. 如何确认补丁生效

```bash
# 1) 架构识别
./build-nccl/bin/llama-server -m model/bolt74b/...gguf --version

# 2) 生产组：启动日志里应出现草稿加载与投机解码信息
... | grep -i -E 'dflash|draft|spec'

# 3) 回退组：启动日志里应出现张量并行相关行
... | grep -i -E 'tensor|split|nccl'

# 4) 门禁开关（仅回退组）
LLAMA_SM_TENSOR_ALLOW_ARCH=1 ./build-nccl/bin/llama-server ... -sm tensor
# 不设置时应报 arch not supported；设置后应进入加载
```

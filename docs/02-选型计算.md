# 02 · 选型计算：我的机器能跑多大模型？

这一章把第一性原理变成一张**可填写的表格**。算完你会得到：

1. 模型文件最大能有多大；
2. 该选哪个量化；
3. 用几张卡、哪种切分；
4. 预期 tok/s 大概是多少。

---

## 1. 先收集四个数

```bash
# 1) 显卡型号、单卡显存、显存带宽（型号可查 techpowerup）
nvidia-smi --query-gpu=index,name,memory.total --format=csv

# 2) 物理内存（GiB）
free -g

# 3) 模型盘类型与速度（USB2 / SATA / NVMe）
lsblk -o NAME,TRAN,SIZE,MODEL
sudo hdparm -tT /dev/sdX       # 或直接看历史加载时间

# 4) PCIe 链路（Gen3 x8 / x4 会影响 all-reduce）
nvidia-smi --query-gpu=pcie.link.gen.current,pcie.link.width.current --format=csv
```

本机结果：

| 项 | 值 |
|---|---|
| GPU | 3 × RTX 3060 12 GB（GA106，360 GB/s 标称，sm_86） |
| 显存合计 | 34.42 GiB |
| 内存 | 46.9 GiB DDR4，实测顺序读 44.7 GB/s |
| PCIe | Gen3 x8 / x4 / x8，H2D 5.98 / 3.12 / 5.98 GB/s |
| 模型盘 | USB2，43.8 MB/s |

---

## 2. 算模型文件上限

```
模型文件上限 = 物理内存 − 系统余量
系统余量 = 6 ~ 8 GiB（46 GiB 内存取 7 GiB；32 GiB 取 6 GiB；64+ 可取 8–10 GiB）
```

本机：`46.9 − 7 = 39.9 GiB`。

**这是硬上限，不是建议。** 超过它的模型会在推理时被内核驱逐页，速度掉一个数量级。

### 2.1 为什么不能"用 swap 补"

swap 也在磁盘上。模型页被换出后再换入，等价于从磁盘读权重。
`MemorySwapMax=0` 是故意的：宁可 OOM 报错，也不要静默地掉到 0.04 tok/s。

## 3. 选量化：从大到小试

### 3.1 Bolt 74B 的可选量化（ModelScope `unsloth/...`）

| 文件 | 大小 | 能否进内存 | 能否全进 3 卡显存 | 建议 |
|---|---:|---|---|---|
| `IQ2_XXS` | 20.5 GiB | ✅ 余量 26 GiB | ✅ | **本项目主力** |
| `UD-IQ2_XXS` | 20.5 GiB | ✅ | ✅ | 与上面接近，可替代 |
| `UD-IQ1_M` | 18.9 GiB | ✅ | ✅ | 更小但质量更差 |
| `UD-IQ1_S` | 17.2 GiB | ✅ | ✅ | 极限压缩，不推荐 |
| `UD-IQ3_XXS` | 29.4 GiB | ✅ 余量 17 GiB | ⚠️ 加 KV/缓冲后紧张 | 内存够、显存不够时考虑 |
| `UD-Q2_K_XL` | 26.8 GiB | ✅ | ⚠️ | 质量/体积折中 |
| `UD-Q3_K_XL` | 36.3 GiB | ⚠️ 余量 10 GiB | ❌ | 层切分可试，TP 装不下 |
| `AD-IQ4_XS` | 43.4 GiB | ❌ 余量 3.5 GiB | ❌ | **实测掉盘，不要用** |

> 命名：`AD` / `UD` 是量化提供方的动态量化策略前缀，不影响加载方式；
> 关键是文件大小和 bpw。

### 3.2 选择顺序

```text
1. 先排除 文件 > 内存 − 7 GiB 的
2. 再排除 每卡权重 + KV + 缓冲 > 单卡显存 的
3. 在剩下的里面选 精度最高 的
4. 如果都装不下 → 降上下文 / 降 -ub / 改层切分 / 加内存
```

本机：

```text
1. 上限 39.9 GiB → 排除 IQ4_XS(43.4)、Q3_K_XL(36.3 勉强)
2. TP+1M：每卡 6.8 + 2.25 + 1.2 = 10.3 < 12 ✅（IQ2）
   TP+1M 用 IQ3：每卡 9.8 + 2.25 + 1.2 = 13.3 > 12 ❌
3. 选 IQ2_XXS
```

## 4. 算每卡显存

```
每卡显存 = 权重/卡数 + KV/卡 + 计算缓冲 + 运行时开销
```

### 4.1 权重

```
每卡权重 = 模型字节数 / 卡数
```

22,018,326,464 B / 3 ≈ 6.84 GiB。

### 4.2 KV 缓存

```
KV 字节 = 2 × 注意力层数 × KV 头数 × head_dim × 上下文 × 每元素字节
```

Bolt 74B：注意力层 8，KV 头 2，head_dim 128。

| 上下文 | 类型 | 每份 | 张量并行 3 卡 |
|---:|---|---:|---|
| 32K | q8_0 | ≈136 MiB | 每卡镜像 136 MiB |
| 200K | q8_0 | ≈850 MiB | 每卡镜像 850 MiB |
| 262K（原生） | q8_0 | ≈1.1 GiB | 每卡镜像 1.1 GiB |
| 1M | q4_0 | ≈2.25 GiB | 每卡镜像 2.25 GiB |
| 1M | q8_0 | ≈4.3 GiB | 装不下 |

**镜像规则**：如果 `卡数 > KV 头数`，每张卡都要存一份完整 KV。
本模型 2 个 KV 头 < 3 张卡 → 镜像。

### 4.3 计算缓冲

计算缓冲（compute buffer）随 `-ub`（物理批大小）和上下文增长，主要因为注意力 mask：

| 配置 | 缓冲/卡（约） |
|---|---:|
| `-ub 128`，1M | 1.2 GiB |
| `-ub 256`，1M | > 2 GiB（实测 device 2 OOM） |
| `-ub 512`，200K，层切分 | 3.2 GiB（三卡分摊后每卡不同） |

**经验**：1M 上下文时 `-ub` 不要超过 128；`-ub 64` 可以再省约 0.3 GiB，速度基本不变。

### 4.4 代入本机

```text
每卡 = 6.84（权重） + 2.25（1M q4_0 镜像） + 1.2（缓冲） + 0.3（运行时）
     ≈ 10.6 GiB
12 GiB 卡剩余约 1.4 GiB  → 原版 IQ2 可以；但实测 11.1/11.3/11.8，已接近极限
```

原版 IQ2 在 1M 下实测差约 1 GiB，所以有了 19.58 GiB 的 tpfit（每卡少约 0.35 GiB）。
**tpfit 的全部意义就是把最后 1 GiB 挤出来。**

## 5. 选切分方式

```text
卡数 == 1            → 不需要切分
卡数 >= 3 且要单流快   → -sm tensor -ts 1,1,1
要最快预填充/长提示    → -sm layer
KV 头数 < 卡数         → TP 会镜像 KV，先确认显存够
显存不够、内存够       → -sm layer + -cmoe（专家缓存）
```

| 方案 | decode | prefill | 适用 |
|---|---:|---:|---|
| 层切分 | 40.3 | 1489 | 长提示、显存紧、简单稳定 |
| 张量并行 3 卡 | 46.4 | 940 | 单流聊天、追求 decode |
| 张量并行 2 卡 | 45.4 | — | 卡不够 3 张 |
| `-cmoe` | 35.7 | 慢 | 显存装不下全部权重，但内存够 |
| `-ncmoe N` | 35.0 | — | 同上，按层留 CPU |

**注意**：`-cmoe` 与 `-sm tensor` 互斥（llama.cpp 直接抛异常）。

## 6. 预期速度估算

```
每 token 字节 ≈ 稠密权重 + (top_k / 专家数) × 专家权重
预期 tok/s   ≈ 有效带宽 × 卡数 ÷ 每 token 字节 × 通信折扣
```

- 单卡有效带宽：batch=1 取标称的 55%（3060：197 GB/s）；
- 张力并行通信折扣：3 卡约 0.55–0.6（本机 46 / 85 ≈ 0.54）；
- 层切分折扣：0.9（只有一张卡工作，但无通信）。

本机核对：

```text
层切分：197 / 4.88 GiB ≈ 40.4 tok/s  → 实测 40.27 ✅
TP 3 卡：197×3/4.88×0.38 ≈ 46       → 实测 46.4 ✅（0.38 是本机的通信+固定开销折扣）
```

**这个估算的用途不是精确预测，而是判断"值不值得试"**：
如果算出来只有 3 tok/s，就别下载了。

## 7. 一张决策表（可直接抄）

| 你的机器 | 建议 |
|---|---|
| 1 × 24 GB | 20–30B 的 4 bit 模型；74B 不要想 |
| 2 × 12 GB + 32 GB RAM | 20B 4bit，或 30B 3bit；74B IQ2 放不下 |
| 3 × 12 GB + 32 GB RAM | 74B IQ2 **内存不够**（需 ≥28 GB）→ 换 30B 或加内存 |
| **3 × 12 GB + 48 GB RAM** | **本配置**：74B IQ2 + TP/层切分 |
| 4 × 12 GB + 64 GB RAM | 74B IQ3 + TP，质量更好 |
| 2 × 24 GB + 64 GB RAM | 74B IQ3/IQ4 + 层切分，prefill 更快 |
| 1 × 48 GB（或 2×24） | 70B 4bit 可以，74B IQ4 边缘 |

## 8. 动手前的检查清单

- [ ] `free -g` 的内存 ≥ 模型文件 + 7 GiB
- [ ] 每卡显存 ≥ 权重/卡 + KV/卡 + 1.2 GiB
- [ ] 模型盘至少有 2 × 模型大小的空余（下载分块 + 最终文件）
- [ ] 已确认 NCCL 可用（张量并行必需）
- [ ] 已确认 `-sm tensor` 对 `nemotron_h_moe` 默认关闭，需要补丁 + 环境变量
- [ ] 已确认模型架构被本地 llama.cpp 识别（先跑小测试或看日志）
- [ ] 知道回退方案（层切分 + 更低上下文）

检查完就可以进入 [03-编译引擎](03-编译引擎.md)。

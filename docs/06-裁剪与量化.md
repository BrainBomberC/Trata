# 06 · 裁剪与量化：生成 `-tpfit.gguf`

> 先纠正一个说法：这一步**不是剪枝（pruning）**。
> 没有删除任何神经元、没有改变模型结构、参数量仍然是 74B。
> 它做的是**混合精度重量化（requantization）**：把不同张量放到不同的存储精度上。

---

## 1. 为什么需要 tpfit

**先说结论：本版生产配置（层切分 + 草稿 + 1M）不需要 tpfit**，直接用原版 IQ2。
tpfit 是给**旧的回退配置**（3 卡张量并行 + 1M，`-ub 128`）压显存用的。

回退配置的每卡预算：

```
权重 6.84 GiB + 镜像 KV 2.25 GiB + 计算缓冲 1.2 GiB + 运行时 ≈ 10.6 GiB
```

12 GB 卡看似够，但实测原版 IQ2 在 `-ub 128` 下会差约 **1 GiB**：

- KV 只有 2 个头，3 卡无法按头切，每卡镜像一份；
- 1M 上下文的 KQ mask 让计算缓冲比 200K 时大；
- 三卡里最紧的一张先 OOM。

tpfit 把文件从 **22,018,326,464 B（20.51 GiB）** 降到 **21,025,816,576 B（19.58 GiB）**，
每卡少约 0.31 GiB。**这 1 GiB 就是它存在的全部理由。**

> 后来发现把 `-ub` 从 128 降到 64 也能装下原版 IQ2，速度基本不变，
> 所以 `scripts/run-tp.sh` 的默认已经改成**原版 IQ2 + `-ub 64`**，tpfit 变成可选。

其它路线：

- 生产：原版 IQ2 + `-sm layer` + DFlash 草稿 + 1M：**54–55 tok/s**（本章不需要）；
- 回退：原版 IQ2 + `-sm tensor -c 1048576 -ub 64`：46.6–47.7 tok/s（也不需要 tpfit）；
- 只有在 TP + 1M + `-ub 128` 或显存特别紧时，才值得花时间量化 tpfit。

## 2. 配方从哪来

`benchmarks/logs/requant-tpfit.log` 是原始量化日志。汇总后：

| 张量 | 数量 | 目标类型 | 理由 |
|---|---:|---|---|
| `ssm_in.weight` | 40 | `q3_K` | 每 token 必读 1.22 GiB，占流量最大；降精度收益最高 |
| `ssm_out.weight` | 40 | `q3_K` | 每 token 必读 0.54 GiB |
| `ffn_down_exps.weight` | 40 | `iq2_xxs` | 专家：保持原精度 |
| `ffn_down_shexp.weight` | 40 | `iq2_xxs` | 共享专家：保持原精度 |
| `ffn_up_exps.weight` | 40 | `iq2_xxs` | 专家：保持原精度 |
| `ffn_up_shexp.weight` | 40 | `iq2_xxs` | 共享专家：保持原精度 |
| 其余稠密张量 | — | `q6_K` | 注意力/latent/embed/output：精度优先 |

一共 **240 条显式规则**（40×2 + 40×4），其余走默认目标 `Q6_K`。

### 2.1 为什么专家不降

- 专家已经是最低的 `IQ2_XXS`（2.38 bpw 的平均值主要来自它们）；
- 再降需要 IQ1 系列，质量明显退化；
- 专家每 token 只读 9 个，对速度贡献小（0.36 GiB / 4.88 GiB）；
- **动专家不划算**：省不了多少字节，却显著伤质量。

### 2.2 为什么 SSM 降得最狠

`ssm_in` + `ssm_out` 每 token 共 **1.76 GiB**，占 4.88 GiB 的 36%。
把它们从 Q6_K 降到 Q3_K，直接减少每 token 流量，且 SSM 投影对量化相对鲁棒。

### 2.3 为什么其余用 Q6_K

注意力层只有 8 层、latent 很小、embed/output 影响输出分布。
这些张量总量不大，用 Q6_K 保住质量，性价比最高。

## 3. 前置条件

| 项 | 要求 |
|---|---|
| 输入模型 | **官方 IQ2_XXS**（专家已经是 `iq2_xxs`） |
| 磁盘 | 至少 45 GB 空闲（读 22 GB + 写 21 GB + 余量） |
| 内存 | 量化过程会 mmap 输入；建议 ≥ 32 GB |
| 工具 | 已编译的 `llama-quantize`（含 0003 补丁） |
| 时间 | 本机约 **12 分钟**（日志：726,953 ms） |

> 如果你从别的量化（IQ3/IQ4/Q4_K）开始，专家类型不是 `iq2_xxs`，
> 目标 IQ2_XXS 需要 imatrix，本脚本会失败或质量不可控。**必须用官方 IQ2_XXS 作输入。**

## 4. 生成逐张量类型清单

`llama-quantize --tensor-type-file` 的格式是：

```
blk.0.ssm_in.weight=q3_K
blk.1.ffn_down_exps.weight=iq2_xxs
...
```

用脚本自动生成（避免手写 240 行出错）：

```bash
python3 -I scripts/gen-expert-types.py \
  model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS.gguf \
  /tmp/tpfit-types.txt --tpfit
```

预期输出：

```
写出 240 条规则 -> /tmp/tpfit-types.txt
类型分布: {'q3_K': 80, 'iq2_xxs': 160}
```

检查几行：

```bash
head -5 /tmp/tpfit-types.txt
grep -c '=iq2_xxs' /tmp/tpfit-types.txt   # 160
grep -c '=q3_K'    /tmp/tpfit-types.txt   # 80
```

## 5. 运行量化

`scripts/quantize-tpfit.sh` 封装了完整流程：

```bash
bash scripts/quantize-tpfit.sh
```

等价的手工命令：

```bash
./llama.cpp/build-nccl/bin/llama-quantize \
  --allow-requantize \
  --tensor-type-file /tmp/tpfit-types.txt \
  --token-embedding-type Q6_K \
  model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS.gguf \
  model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS-tpfit.gguf \
  Q6_K
```

### 5.1 参数解释

| 参数 | 为什么 |
|---|---|
| `--allow-requantize` | 输入已经是量化过的，允许再次量化 |
| `--tensor-type-file` | 逐张量覆盖类型；**必须放在位置参数之前** |
| `--token-embedding-type Q6_K` | 词嵌入单独指定（日志显示 q8_0 → q6_K） |
| 最后一个 `Q6_K` | 默认目标类型，覆盖清单里没有列出的张量 |

> **顺序陷阱**：`llama-quantize` 只解析位置参数**之前**的选项。
> 把 `--tensor-type-file` 放到输入/输出文件名后面，会被当成多余参数忽略，配方静默失效。

### 5.2 预期日志

开头：

```
llama_quantize: quantizing '...IQ2_XXS.gguf' to '...IQ2_XXS-tpfit.gguf' as Q6_K
```

中间：

```
blk.0.ssm_in.weight  - [...], type = nvfp4, converting to q3_K ...
blk.1.ffn_down_exps.weight - [...], type = iq2_xxs, size = ...
```

注意专家张量**没有** `converting to`——0003 补丁跳过了同类型重量化。

结尾：

```
llama_model_quantize_impl: model size  = 20990.75 MiB (2.38 BPW)
llama_model_quantize_impl: quant size  = 20044.22 MiB (2.27 BPW)
llama_quantize: quantize time = 726953.15 ms
```

### 5.3 验证输出

```bash
stat -c '%s %n' model/bolt74b/*tpfit.gguf
# 预期：21025816576 ...-tpfit.gguf
```

大小对上基本就成功了。再做一次加载测试：

```bash
LLAMA_SM_TENSOR_ALLOW_ARCH=1 \
./llama.cpp/build-nccl/bin/llama-server \
  -m model/bolt74b/NVIDIA-Nemotron-3.5-Bolt-74B-A9B-IQ2_XXS-tpfit.gguf \
  -ngl 0 --no-warmup 2>&1 | head -40
```

看到 `model loaded` 即可（`-ngl 0` 只用 CPU 验证元数据，不占显存）。

## 6. 质量：tpfit 会不会更差

会，但幅度可控：

- 专家（决定模型容量的主体）**完全没动**；
- SSM 投影从 Q6_K 降到 Q3_K，是主要损失来源；
- 其余稠密张量从 q8_0/nvfp4 到 Q6_K，基本无损。

原始 IQ2_XXS 的 wikitext-2 PPL 是 **5.7589 ± 0.0357**。tpfit 的 PPL 本项目未单独测，
但按经验，SSM 降到 Q3_K 的损失在 1–3% 量级。

**如果你更看重质量、不需要 1M**：直接用原版 IQ2 + 层切分，不要 tpfit。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `--tensor-type-file` 没生效 | 放到了位置参数后面 | 移到最前 |
| `imatrix required` | 输入专家不是 iq2_xxs | 换官方 IQ2_XXS 输入 |
| 输出比输入还大 | 默认类型选错 / 清单没生效 | 检查 `Q6_K` 与清单路径 |
| 量化到一半磁盘满 | 需要 2× 文件空间 | 清理磁盘后重跑（会覆盖） |
| 量化极慢（几小时） | 从 USB2 盘读写 | 先把输入拷到 NVMe |
| 输出加载时报张量形状错误 | 补丁 0001 没打 | 回到 [04-补丁说明](04-补丁说明.md) |
